## Souhrn epiku

Epic 4 dokončil 5 z 5 stories a přinesl zásadní vylepšení TsFormEditoru v oblasti správy polí, validace a datové synchronizace. Hlavní přínosy: atomické přejmenování polí s propagací do celého layoutu, vkládání sloupců na specifickou pozici v mřížce, real-time validace unikátnosti a formátu klíčů polí s plnou a11y podporou, a kompletní synchronizace import/export s novým typovým systémem (TsFormDef/TsRowItem/TsButton) včetně zpětné kompatibility se starším formátem.

Během dvou kol adversarial code review byly zachyceny a opraveny všechny nálezy — od typových anotací přes a11y přístupnost tlačítka vkládání sloupců až po robustnost importu při chybějících referencích na pole.

## Co fungovalo dobře

- Atomický rename flow (`renameField`) je čistě navržen s jasnými guardy (existence → prázdnost → formát → duplicita → stav layoutu → saveToHistory → mutace). Žádná akce se neprovede při nevalidním vstupu.
- VALID_FIELD_KEY regex je exportován ze store a sdílen mezi store guardem i UI validací. Jediný zdroj pravdy pro formát klíče pole.
- Mapovací funkce `mapEditorItemToTsRowItem` a `mapTsRowItemToEditorItem` čistě oddělují interní editor formát od TsForm JSON formátu.
- Testovací pokrytí: 26 testů ve store.test.ts pokrývající rename (12 testů), insertColumnAtPosition (5 testů), import/export sync (9 testů).
- Round-trip testy (export → import → re-export) ověřují, že žádná metadata se neztratí.
- Real-time onChange validace v UI dává uživateli okamžitou zpětnou vazbu bez nutnosti commitu.
- a11y: `aria-invalid`, `aria-describedby`, `role="alert"` na validačních chybách klíče pole.
- Escape reset v poli Field ID umožňuje snadný návrat k původní hodnotě.

## Co nefungovalo dobře

- Insert column button byl zpočátku přístupný pouze myší (opacity-0 group-hover:opacity-100 bez focus-within). Keyboard-only uživatelé tlačítko neviděli. Opraveno ve druhém kole review přidáním `group-focus-within:opacity-100`.
- Insert column button neměl `aria-label` — Lucide Plus ikona je aria-hidden, takže screen readery neměly accessible name. Opraveno.
- `mapTsRowItemToEditorItem` při importu JSON s odkazem na neexistující pole zachovával orphaned field name a nastavoval type na "empty". To vytvářelo nekonzistentní stav. Opraveno — neexistující reference se nyní čistí na `""`.
- Exportní typ `exportJson()` v prvním kole review používal příliš úzkou typovou anotaci místo `TsRowItem[][]`. Opraveno.
- Round-trip test chyběl pro tabs mode s separator/align metadata. Doplněno.

## Klíčové technické poznatky

### Vzory, které se osvědčily

- Guard-first pattern v `renameField`: Všechny validace proběhnou PŘED `saveToHistory()`, takže neúspěšné operace nevytvářejí zbytečné undo záznamy.
- Sdílená regex konstanta (VALID_FIELD_KEY) mezi store a UI zajišťuje konzistentní validaci.
- `Math.max(0, Math.min(itemIndex, row.items.length))` v `insertColumnAtPosition` elegantně řeší boundary clamping.
- Immutabilní state update pattern s array spread/slice/splice v Zustand store.

### Rizikové oblasti

- A11y u hover-only UI elementů vyžaduje explicitní pozornost — `group-hover:opacity-100` MUSÍ být doplněno o `group-focus-within:opacity-100`.
- Import robustnost — JSON z externích zdrojů může obsahovat nekonzistentní field reference. Mapping funkce musí být defenzivní.
- Žádný UI test (React Testing Library) pro validační flow v FieldPropertiesPanel — spoléháme pouze na store unit testy.
